# متجر Cloudflare — نسخة بدون R2

هذه نسخة أساس (MVP) لمتجر عربي RTL باستخدام Cloudflare Workers وD1 وملفات Static Assets. لا تستخدم R2 ولا ترفع صورًا من الجهاز؛ الصور روابط HTTPS خارجية فقط. لا تعتبر هذه النسخة جاهزة لاستقبال مدفوعات أو ملفات رقمية حساسة قبل استكمال الاختبارات والمراجعة.

## قبل النشر

1. استخدمي قاعدة D1 الحالية باسم `luxury_store_db` إذا كانت تحتوي بياناتك.
2. افتحي `wrangler.toml` واستبدلي `REPLACE_WITH_YOUR_D1_DATABASE_ID` بمعرّف D1 الحقيقي. لا تغيّري اسم قاعدة البيانات إذا كانت بياناتك موجودة بالفعل.
3. اسم Worker مضبوط على `market2` ليتوافق مع سجل Cloudflare Builds الذي أرسلتيه. إذا كان اسم Worker الفعلي مختلفًا، اجعلي الاسمين متطابقين.
4. تاريخ التوافق مضبوط على `2026-11-23` لتجنب خطأ التاريخ المستقبلي.
5. في Worker > Settings > Variables and Secrets أضيفي `AUTH_SECRET` و`SETUP_KEY` كـ Secret بقيم عشوائية مستقلة، وأضيفي `ALLOWED_ORIGINS` كنص يساوي أصل الموقع الفعلي مثل `https://market2.workers.dev`.

## قاعدة البيانات

طبّقي migrations بالترتيب على قاعدة D1 المستهدفة مرة واحدة فقط:

```bash
npx wrangler d1 migrations apply luxury_store_db --remote
```

إذا كانت الترحيلات مطبقة بالفعل، لا تعيدي تشغيل SQL يدويًا ولا تحذفي الجداول. افحصي حالة migrations أولًا.

## إنشاء المدير الأول

بعد نجاح النشر وترحيلات D1 افتحي `/setup.html`. أدخلي `SETUP_KEY` واسم مستخدم من 3 إلى 40 حرفًا إنجليزيًا أو أرقامًا أو . _ - وكلمة مرور لا تقل عن 12 حرفًا. بعد إنشاء الحساب افتحي `/admin.html`. واجهة الإعداد لا تنشئ مديرًا ثانيًا لأن API يرفض ذلك بعد وجود المدير الأول.

## فحص سريع

- `/api/health` يجب أن يعرض `ok: true`.
- `/api/public-products` يجب أن يعرض قائمة، وقد تكون فارغة.
- اختبري إنشاء المدير وتسجيل الدخول ومنتجًا وطلبًا تجريبيًا قبل الاستخدام الفعلي.

## حدود النسخة

- الصور الخارجية HTTPS فقط؛ لا رفع من الجهاز ولا R2.
- لا يوجد دفع إلكتروني، تسليم آمن للملفات الرقمية، حسابات عملاء، موظفون وصلاحيات متعددة، نسخ احتياطي/استعادة أو سجل تدقيق شامل.
- تقارير المبيعات تحتسب الطلبات المدفوعة فقط.
- يجب اختبار الطلبات والمخزون والمرتجعات على قاعدة اختبار قبل الإنتاج.
